# DSH Workboard · 工作看板

[![CI](https://github.com/Kamigs/dsh-workboard/actions/workflows/ci.yml/badge.svg)](https://github.com/Kamigs/dsh-workboard/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

一个 DeepSeek Harness（DSH）插件：左侧栏的「工作看板」先进入首页，集中展示完成热力图、所有工作区与独立看板、灵感便签。
点击看板卡片进入常驻三栏（待办 / 进行中 / 已完成）；任务带日期、紧急程度、标签、附件、指派（AI 或当前登录账号）。
AI 任务可以发到会话里讨论或执行，卡片与会话互相跳转。

[English](README.en.md) · [架构说明](docs/ARCHITECTURE.md) · [更新日志](CHANGELOG.md) · [打包发布](docs/RELEASING.md)

## 功能

- **首页入口**：点击左侧栏「工作看板」进入首页，刷新或重启后也从首页开始。看板卡片展示目录和各状态未归档任务数，支持搜索；点击进入原有三栏看板，点击「返回」返回首页。
- **工作区与独立看板**：首页集中展示所有工作区和不绑定目录的独立看板；首次发送独立看板的 AI 任务时再选择工作目录。详情页顶部的看板名称仍可打开切换菜单。
- **完成热力图**：始终展示包含本周在内的最近 52 周，格子和间距随可用宽度缩放；超宽屏增加两侧留白、保持居中。按浏览器本地日期统计，同一任务每天只计一次。从启用此功能后记录完成事件，不根据旧任务的更新时间回填历史；归档或删除任务不抹去完成记录。
- **灵感便签**：全局共享的六色便签，支持快速输入、搜索、正文编辑和删除，卡片底部显示更新时间或保存状态。新便签点击添加或按 `⌘ / Ctrl + Enter` 提交；已有便签停止输入 600ms 后自动保存，失败保留草稿并提供重试。
- **三栏常驻**：待办（灰）/ 进行中（蓝）/ 已完成（绿）；空栏只显示栏内占位，不会把三栏换成整页空状态。
  卡片支持拖拽跨栏、拖到卡片前后插入排序。
- **任务编辑**：使用一个「任务内容」输入框，第一行概括任务、后续补充细节；支持日期、紧急程度、标签、附件和指派。状态由新建所在列决定，之后可拖拽卡片或通过详情、关联任务面板的状态菜单修改。
- **附件**：支持文件选择和拖入文件，不限制附件数量；发送任务时，图片和文件随任务内容一并传入目标会话。
- **任务详情栏**：正文直接显示在任务名称下方，后续展示状态、日期、标签、附件、会话与操作；
  图片附件显示大图 + 全部附件缩略图，视频 / 音频 / 文本 / 其他文件在右侧预览栏打开。
- **发送任务**。点击 AI 卡片的发送箭头，选择新建会话、已关联会话或同工作区可用的当前会话。「先讨论」保留任务状态，「直接执行」在消息入队后将待办移到进行中。完成由用户在看板上确认。
- **关联任务面板**。点击会话右上角的列表按钮，可查看当前会话关联的所有未归档任务。每张卡片都可切换任务状态、跳转到工作看板或打开编辑弹窗。点击面板的加号，可新建任务并自动关联当前会话。
- **归档**。任意状态的任务都可以从详情区归档。归档和恢复只作用于所选卡片。恢复后，卡片回到原列，并保留会话链接。
- **数据导入导出**：「设置 → 工作看板」 —— 导出全部任务为 JSON；也可把 JSON 导入到当前项目（新建任务，不覆盖已有数据；附件文件、会话与归档状态不随导出迁移）。任务 JSON 不包含便签和完成历史。
- **可调宽度**：看板与详情之间有垂直拖动手柄，宽度会记住（localStorage，刷新/重开面板后保持），双击复位；上限随窗口自适应，保证三栏不被挤扁。
- **与 DSH 一致**：图标直接使用宿主导出，首页按钮、输入框、行内编辑、提示和弹窗直接复用 DSH UI primitives。沿用 `--dsw-*` 设计令牌、亮/暗主题、中英文案；便签六色色相与宿主背景混合，正文使用宿主文字色。

## 环境要求

- 已实测 DeepSeek Harness `0.2.1-rc.5` 的 Desktop / Web profile。
- `engines.dsh` 声明范围为 `>=0.2.1-rc.5 <0.3.0`；这不是对范围内所有版本的实测保证。
  DSH 的客户端 API 仍在迭代，升级后需重新验收。该范围不包含其他版本号的预发布版。
- Node.js >= 22。插件无 npm 运行依赖；React 和 DSH UI 组件由宿主客户端模块表提供。

## 安装

本项目是 DSH **Bundle 插件**，根目录的 `package.json` 与 `cordis.patch.yml`
一起声明加载方式。浏览器产物 `lib/client.js` 已提交，用户安装预构建包无需编译。
以下命令使用已安装的 `dsh` CLI；Desktop 使用 `desktop` profile，Web 使用 `web`。

### 从本地安装包安装

先在开发目录执行 `npm run pack`，它会构建、检查并生成安装包，然后执行：

```sh
dsh plugin --profile desktop add ./dist/dsh-workboard-0.1.0.tgz
```

重启对应的 DSH 实例后，左侧栏会出现「工作看板」。Web 用户将 `desktop` 改为 `web`。

### 从本地目录开发

在插件根目录执行：

```sh
npm run build
dsh plugin --profile desktop add .
```

本地目录以链接方式安装。修改浏览器源码后运行 `npm run build` 并刷新页面；
修改 Host 代码或 manifest 后重新加载插件或重启对应实例。

### 公开发布后的安装方式

GitHub 仓库和 npm 包的公开发布需单独完成；下面的命令用于发布之后：

```sh
# GitHub：仓库必须包含已构建的 lib/client.js
dsh plugin --profile desktop add github:Kamigs/dsh-workboard

# npm：仅在对应版本已发布后可用
dsh plugin --profile desktop add dsh-workboard@0.1.0
```

发布包包含预构建入口，不声明 `prepare`、`install` 或 `postinstall`。
生产使用可把 GitHub 来源固定到已验证的提交或标签。发布步骤见[打包发布](docs/RELEASING.md)。

## 使用

1. 点左侧栏的看板图标进入首页，查看完成热力图、全部看板和灵感便签。
2. 点击看板卡片进入三栏详情，或点击「新建看板」创建独立看板。详情页顶部可切换看板；点击「返回」或侧栏入口返回首页。会话中的任务跳转仍会直接打开所属看板与任务。
3. 点击列头的 `+` 在该列新建任务。在「任务内容」第一行概括任务，下面补充细节。
4. 指派选 **AI** 的任务，卡片右下角出现蓝色圆形发送按钮，点击后选择目标和发送方式。
5. 点击卡片打开右侧详情，点击当前状态可将卡片移入目标列。
6. 点击详情底部的「归档任务」。点击右上角齿轮进入「设置 → 工作看板」，归档区按看板常驻展示最近三项归档任务，可展开其余任务、恢复或删除。
7. 设置页的「看板列表」纵向展示全部看板，右侧编辑图标支持就地改名，Enter 保存、Esc 取消；列表右上角可以新建看板。选择列表中的看板作为导入目标，`导入数据` 选择 JSON 后确认导入，`导出数据` 下载全部看板的任务。
8. 在首页输入灵感并选择颜色，点击「添加便签」保存。已有便签通过底部编辑按钮修改，修改自动保存；遇到失败可点击「重试保存」。删除便签需要确认。

## 数据与配置

- 任务、看板、全局便签和完成事件：`$DSH_HOME/kanban/state.json`（`DSH_HOME` 缺省为 `~/.dsh`）。便签不归属于某个工作区。
- 完成事件在任务新建为「已完成」或由其他状态进入「已完成」时写入；同日重复完成在热力图中去重。导入的已完成任务是新建任务，计入导入当天，不恢复来源的完成日期。
- 未提交便签和待保存编辑保存在浏览器 `localStorage` 的 `dsh-workboard:note-drafts` 中，刷新后可继续编辑或重试；浏览器存储不可用时只保留内存草稿。它不替代已保存数据的备份。
- 附件：默认存放在**任务所属工作区**的 `<工作区>/.dsh/assets/kanban/` 下（文件名 `<附件 id>-<原名>`），
  插件数据目录里的 `attachments/index.json` 只记录名称 / 类型 / 大小与工作区引用；旧数据仍兼容读取。
  插件不设置附件数量和单文件大小上限；传输仍受请求体上限 256 MiB 及 DSH Connection 请求体限制影响。
  如果不想让 `.dsh/` 进入项目版本库，记得在项目根 `.gitignore` 里忽略它。
- 写入是串行的：同目录临时文件 + `fsync` + `rename` 原子发布；损坏的状态文件会被备份为
  `state.json.corrupt-<时间戳>`，插件以空看板启动而不是启动失败。
- 可选配置：在 profile 的 `cordis.patch.yml` 覆盖 `kanban` 行的 `config.dataDir`：

  ```yaml
  - id: kanban
    config:
      dataDir: ~/Documents/kanban
  ```

- 看板、便签、完成记录和附件保存在本机；发送 AI 任务时，内容和附件会交给目标会话所使用的模型。插件的 HTTP 接口挂在 DSH Connection 的 `/api` 认证通道下，
  仅接受本机已登录的浏览器会话。

## 开发

```sh
npm run build     # 拼接 src/client/parts -> lib/client.js
npm test          # 存储、归档、发送流程、首页统计与便签保存测试
npm run test:smoke  # Host 路由端到端 + 浏览器半渲染冒烟（无需浏览器）
npm run check     # 以上全部 + 静态校验
npm run pack      # 全部检查 + 打包 + 隔离安装包冒烟，输出 dist/
```

详见 [CONTRIBUTING.md](CONTRIBUTING.md) 与 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)。

## 项目结构

```
index.js                  Host 插件入口（注入 connection / workspaceRegistry）
host/store.js             任务/便签/完成事件模型、校验、原子持久化、附件
host/routes.js            /api/kanban.* 认证 JSON 接口
lib/client.js             构建产物：浏览器包（提交在仓库里）
src/client/parts/*.js     浏览器源码分段，按序拼进同一个 factory 作用域
scripts/                  构建、静态校验、冒烟检查和安装包验证
test/                     存储、归档、发送流程、首页与便签测试
locale/                   插件面板展示用的中英文元数据
icon.svg, cordis.patch.yml
docs/                     架构说明与打包发布步骤
dist/                     已验证的 .tgz 与 SHA-256（生成目录，不提交 Git）
```

开发目录保留源码与测试；安装包只带运行文件、图标、本地化和文档。
`host/` 是无需编译的 JavaScript 运行源码，`lib/` 是提交到 Git 的浏览器构建产物。

## 说明

- 首页、发送弹窗和会话任务面板直接使用 Harness 提供的 UI 组件；图标直接引用宿主导出。
- 登录账号信息通过可选的 `ctx.remote.account.getProfile` 读取；未登录或该 remote 不可用时，
  负责人自动降级为普通「人工」，不影响其它功能。
